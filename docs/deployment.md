# Deployment — Durable production (Sprint 13.1 / 14)

**Not production:** Cloudflare Quick Tunnels (`scripts/start_public_host.py`) are **PREVIEW only**. They die with the process and must never be reported as the public production URL.

Durable production is the Render Blueprint host:

**Public app:** `https://ados-web.onrender.com`

Casino play-money foundation (Sprint 15) is served on the same origin:
`/casino`, `/casino/venues/odessa-prime`, `/api/casino/v1`. No payment processing.

1. **Render Blueprint** (`render.yaml`) — git-driven web service + managed Postgres + Redis (live)
2. **Self-managed compose** (`docker-compose.prod.yml`) — VPS with DNS/TLS via `scripts/deploy_production.sh` (engineering path)

No deployment secrets live in git.

## Durable production (Render Blueprint)

The IaC definition is **`render.yaml`**:

| Component | Definition |
|-----------|------------|
| Web service `ados-web` | Docker (`Dockerfile.web`) — API + same-origin SPA via `scripts/run_production_web.py` |
| PostgreSQL `ados-postgres` | Render managed Postgres (source of truth) |
| Redis `ados-redis` | Render Key Value (required by production config policy) |

**Topology:** one process serves `/` (production `src/web/dist` build, `ADOS_SERVE_WEB=true`),
`/api/*`, `/management/*`, `/liveness`, `/readiness`, `/health`, `/metrics` on
`https://ados-web.onrender.com`. 3D city assets are same-origin under `/assets/odessa/`;
browser navigation to `/city` and `/enterprise-city` serves the SPA. Telegram polling is
*not* part of this service (`ADOS_TELEGRAM_REQUIRED=false` — explicit web profile); the bot
remains a separate run target.

**Migrations:** `scripts/run_production_web.py` runs `alembic upgrade head` at startup and
**refuses to start production** if migrations fail (`ADOS_SKIP_MIGRATIONS=1` only for
out-of-band migration flows). Provider `postgresql://` URLs are normalized to
`postgresql+asyncpg://` automatically (ConfigurationCenter + `migrations/env.py`).

**Deploy trigger (CI/CD):** push to `develop` → `.github/workflows/production-gate.yml`
and `.github/workflows/production-foundation.yml` → Render `autoDeployTrigger: checksPass`
deploys only when checks pass. A failed gate, build, or `/liveness` check never replaces a
healthy deployment.

**External verification:** `.github/workflows/production-verify.yml` (scheduled + manual).
Configure the repository **variable** `PRODUCTION_URL` to enable it.

**Secrets (NAMES only, never values):** `IAM_JWT_SECRET`, `JWT_SECRET`, `API_JWT_SECRET`,
`SECURITY_MASTER_KEY` are **generated by Render** at provision time (`generateValue`);
`DATABASE_URL` / `REDIS_URL` are injected from the managed services; `BOT_TOKEN` is optional
(`sync: false`). No deployment secrets exist in the repo.

**One-time owner action (blueprint activation):** Render dashboard → *New +* → *Blueprint* →
connect `okeysiri11/telegram-ai-crm-bot` → apply `render.yaml` → after first deploy, set the
GitHub repository variable `PRODUCTION_URL` to the service URL.

## Durable production (self-managed compose)

| Layer | Compose / path |
|-------|----------------|
| App API | `bot` service · Dockerfile |
| Postgres / Redis | `docker-compose.prod.yml` (Postgres is not published) |
| Edge | `nginx.conf` (SPA + `/api` + `/liveness` `/readiness` `/health`) |
| Identity | `GIT_SHA` / health `revision` |

See [ENVIRONMENT_CONTRACT.md](./ENVIRONMENT_CONTRACT.md). Never commit `.env.production`.

```bash
python scripts/production_doctor.py --offline
./scripts/deploy_production.sh
curl -fsS http://localhost/liveness
```

Compose rollback: [PRODUCTION_ROLLBACK.md](./PRODUCTION_ROLLBACK.md). Render rollback: dashboard → Deploys → Rollback.

## Preview host (tunnel mode — not production)

`scripts/start_public_host.py` can front a **production SPA build** for a short-lived demo.
The hostname is ephemeral.

```bash
npx vite build            # in src/web — production SPA build
.venv/bin/python scripts/start_public_host.py
# preview URL written to data/public_host.url (ephemeral: dies with the process)
```

See `docs/SPRINT_13_PRODUCTION_HOST_RECOVERY_RESULT.md` for the Sprint 13 recovery record.

## TLS (compose)

Uncomment the TLS server block in `nginx.conf` and mount certs under `/etc/nginx/certs/`.
