# ADOS Enterprise SDK

## Purpose

The **ADOS SDK** is the extension system that allows **developers, partners, and future AI agents** to extend ADOS **without modifying the Core**.

All supported extensions—business features, providers, UI, workflows, analytics, automation, security, and connectors—ship as **plugins** that use stable SDK APIs, declare manifests, honor permissions, and follow a governed lifecycle.

This package is **documentation only**. Do **not** modify application code as part of this design.

## Goals

| Goal | Meaning |
|------|---------|
| **Stable APIs** | Versioned SDK surfaces; Core internals are not a public API |
| **Plugin development** | Partners build against SDK + manifest, not forks of Core |
| **Module isolation** | Plugins cannot deep-import peer business modules or Core private code |
| **Version compatibility** | Manifest Compatibility + semver; broken plugins fail closed |
| **Extension lifecycle** | Install → … → Remove with health, enable/disable, upgrade |

## Non-negotiable rules

1. **SDK is the only supported extension point** for third parties and additive product packs.  
2. **Core remains stable/frozen** for extension purposes—plugins inject; they do not patch Core.  
3. **No business logic in provider plugins** beyond adapter mapping (aligns with UPP).  
4. **Permissions are deny-by-default** ([[PERMISSION_MODEL]]).  
5. **Hooks observe/extend; they do not silently bypass Architect/Security gates.**  
6. Unsigned or incompatible plugins are not Enableable in enterprise editions ([[PLUGIN_STORE]]).

## Success criteria

- New capability ships as a plugin without Core edits.  
- Runtime/OS consume plugins via Plugin Manager + registries.  
- Agents generated by Factory use SDK APIs the same way human developers do.
